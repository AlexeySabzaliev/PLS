# Руководство пользователя ПЛС (УСС + УЗнТ)

## 1. Ролевая модель и доступы

В системе работают три операционные роли и одна административная:

| Роль | Основные функции | Доступ к отчетам |
|------|------------------|------------------|
| **Транспортная логистика** | Ведение таблицы ТС, ввод данных по прибытию/убытию, заполнение отчета по транспортным операциям. | Отчет по ТС (основной драйвер дня). |
| **Складская логистика** | Ввод данных по обработке груза (ручная/механизированная), сменные отчеты. | Сменный отчет склада. |
| **Управление запасами** | Инвентаризация, учет площадей, доп. услуги не связанные с ТС. | Отчет по управлению запасами. |
| **Коммерческая логистика** | **Администрирование дней**: открытие/закрытие дат, коррекция подтвержденных данных, управление ставками. | Полный доступ ко всем отчетам и биллингу. |

## 2. Процесс работы с днем (Daily Workflow)

Система работает по принципу **"Закрытого дня"**. Данные за прошедшую дату считаются окончательными только после подтверждения всеми ответственными лицами.

### 2.1. Статусы дня
День имеет один из следующих статусов, отображаемых в интерфейсе:
*   **День открыт**: Работа идет, данные можно менять.
*   **Частично подтверждено (X/3)**: Некоторые роли уже завершили работу, но день еще открыт для остальных.
*   **День закрыт**: Все 3 роли подтвердили отчеты. Изменения заблокированы.

### 2.2. Механизм подтверждения (Правило 3/3)
Для того чтобы день считался закрытым, необходимо выполнение условия **3/3**:
1.  **Транспортная логистика** заполняет отчет по ТС и нажимает кнопку **"Подтвердить день"**.
2.  **Складская логистика** заполняет сменный отчет и нажимает кнопку **"Подтвердить день"**.
3.  **Управление запасами** заполняет отчет и нажимает кнопку **"Подтвердить день"**.

> **Важно:** Даже если одна роль не внесла данных (нулевой отчет), она все равно должна явно подтвердить, что работа за день завершена ("подтвердить пустоту").

### 2.3. Блокировка изменений
*   Как только пользователь нажал "Подтвердить день", его раздел отчета блокируется для редактирования.
*   Если статус дня стал **3/3 (Закрыт)**, редактирование блокируется для **всех** операционных ролей.
*   **Исключение:** Только роль **Коммерческая логистика** может принудительно "Открыть день" заново для внесения исправлений (например, при обнаружении ошибки постфактум).

## 3. Биллинг и расчеты

### 3.1. Предварительный биллинг
*   Формируется автоматически в момент закрытия дня (статус 3/3).
*   Содержит расчеты стоимости услуг на основе актуальных ставок на конкретную дату.
*   **Назначение:** Позволяет видеть предварительную сумму затрат/доходов за день даже внутри длинного периода (месяца), где ставки могли меняться.

### 3.2. Финальный биллинг
*   Формируется по окончании расчетного периода (обычно месяц).
*   Агрегирует данные предварительного биллинга за все дни периода.
*   Учитывает изменения ставок задним числом (если день был перепроведен коммерческой ролью).
*   Готовится к выгрузке для отправки клиенту.

### 3.3. Влияние на отчеты эффективности
*   Отчеты типа "Эффективность ФОТ" или "Выработка на дату" берут данные из закрытого дня.
*   Пока день не закрыт (статус < 3/3), метрики эффективности считаются предварительными.

## 4. Справочники и настройки

### 4.1. Справочник ставок
*   **Параметр "Как считается":**
    *   `Авто (из таблицы ТС)` — система сама считает количество услуг на основе данных в отчете ТС (например, количество машин).
    *   `На строке ТС (Ручной ввод)` — оператор вручную вводит количество услуг для каждой машины (например, "Доп. комплекты документов").
    *   `Авто (Параметр ДС)` — берется фиксированное значение из Договора Склада.
*   **Изменение параметра:** Доступно для изменения в любой момент, но применяется к новым расчетам. Для пересчета прошлых периодов требуется перепроведение дней.

### 4.2. Импорт данных (Портал охраны)
*   Система автоматически подтягивает данные о ТС с портала охраны.
*   **Нормализация номеров:**
    *   Все пробелы удаляются.
    *   Регистр приводится к верхнему.
    *   Формат: `НОМЕР_ТЯГАЧА[/НОМЕР_ПРИЦЕПА]`.
    *   Пример: `А 123 АА / В 456 ВВ` превращается в `А123АА/В456ВВ`.
    *   Это предотвращает создание дублей записей из-за разного формата ввода номеров.
